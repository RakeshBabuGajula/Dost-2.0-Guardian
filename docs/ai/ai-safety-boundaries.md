# AI Safety Boundaries & Governance: DOST Guardian 2.0

**Governance Framework**: Non-Deterministic AI Isolation Protocol  

---

## 1. Strict Boundary Principles

To prevent catastrophic system failures or missed safety alerts caused by non-deterministic AI behavior (LLM hallucinations, model drift, probabilistic classification errors), DOST Guardian 2.0 enforces a **Strict Boundary Firewall** separating AI subsystems from the Real-Time Safety Engine.

```text
+---------------------------------------------------------------------------------+
|                       REAL-TIME SAFETY PATH (100% DETERMINISTIC)                |
|                                                                                 |
|   [Train Telemetry] ----> [Deterministic SafetyEngine] ----> [Worker Alert]    |
|                                   (NO AI ALLOWED)                               |
+---------------------------------------------------------------------------------+

                                     ||  Read-Only Asynchronous Feed
                                     \/

+---------------------------------------------------------------------------------+
|                       OFFLINE ANALYTICS PATH (AI ASSISTED)                      |
|                                                                                 |
|   [Incident Logs] ----> [pgvector / LLM RAG Pipeline] ----> [Safety Manager]    |
|                               (ANALYTICS ONLY)                                  |
+---------------------------------------------------------------------------------+
```

---

## 2. Permitted AI Capability Matrix

| AI Capability / Module | Allowed Domain | Description & Guardrails | Non-Safety Critical Verification |
| :--- | :--- | :--- | :--- |
| **Near-Miss Spatial Clustering** | Safety Analytics | Unsupervised spatial clustering (DBSCAN / HDBSCAN) to identify recurring near-miss spatial hotspots. | Operates asynchronously on historical database records after shift end. |
| **Post-Incident Summarization** | Executive Reporting | LLM-based natural language summarizer parsing telemetry logs to generate incident audit briefs for Safety Managers. | Must include raw timestamp telemetry attachments; human supervisor must sign off. |
| **Natural Language Query Assistant** | Supervisor Portal | RAG pipeline allowing Safety Managers to query historical logs (e.g., *"Show near-misses in Section MAS-120 last month"*). | Read-only database access via pgvector; zero authority to alter configuration or system state. |
| **Predictive Equipment Maintenance** | Device Management | Classification model predicting worker phone battery degradation or GPS sensor drift. | Flags device for IT inspection; does not alter active session rules. |

---

## 3. Strict AI Prohibitions (What AI CANNOT Do)

1. **PROHIBITION 1**: AI models MUST NOT calculate or override Dynamic Safety Envelopes or Time-to-Danger (TTD) thresholds.
2. **PROHIBITION 2**: AI models MUST NOT independently authorize track entry, work session starts, or work session closeouts.
3. **PROHIBITION 3**: AI models MUST NOT suppress, delay, filter, or alter any safety alert generated by the deterministic engine.
4. **PROHIBITION 4**: AI models MUST NOT generate operational railway instructions (e.g., train routing or signal aspect changes).
5. **PROHIBITION 5**: AI models MUST NOT process real-time telemetry on the critical alert path.
